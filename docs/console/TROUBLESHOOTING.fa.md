# رفع اشکال

از کارت سرور «گزارش اتصال و عملیات» را باز و گزارش JSON را دانلود کنید. شناسهٔ عملیات، زمان، مرحله و کد خطا برای پیگیری کافی‌اند؛ پسورد و کلید را در issue عمومی نگذارید.

| کد / نشانه | بررسی لازم |
| --- | --- |
| SSH_DNS | نام دامنه و DNS ماشین کنسول |
| SSH_TIMEOUT / SSH_TCP | آدرس، پورت SSH، سرویس sshd، مسیر شبکه و فایروال |
| HOST_KEY_CHANGED | تغییر واقعی هویت میزبان را مستقل بررسی کنید؛ کلید جدید را بی‌بررسی قبول نکنید |
| SSH_AUTH | نام کاربر، رمز/کلید، passphrase و مجوز ورود root یا کاربر انتخاب‌شده |
| HELPER_MISSING | آماده‌سازی خودکار را از ابزارهای سرور اجرا کنید |
| HELPER_INCOMPATIBLE | ابزار قبلی قابل اجرا/سازگار نیست؛ نسخه و مجوز فایل را بررسی کنید؛ بازنویسی خودکار انجام نمی‌شود |
| PACKAGE_INVALID | ZIP را کامل استخراج کنید؛ helpers و manifest باید کنار فایل اجرایی باشند |
| UNSUPPORTED_ARCH | ابزار سرور برای Linux amd64 و arm64 است |
| ROOT_REQUIRED / INSTALL_COMMAND | نصب با root یا sudo مجاز بدون رمز؛ پنل sudoers را تغییر نمی‌دهد |
| INSTALL_DIRECTORY / UPLOAD_WRITE | فضای دیسک، inode، دسترسی /usr/local/bin و فقط‌خواندنی نبودن mount |
| CHECKSUM_MISMATCH | انتقال کامل نشده یا فایل خراب است؛ قبل از نصب رد شده؛ بستهٔ معتبر را دوباره بگیرید |
| EXEC_VERSION | معماری، محدودیت noexec و اجرای فایل موقت |
| INSTALL_INTERRUPTED | نتیجهٔ نصب نامشخص؛ اجرای دوبارهٔ آماده‌سازی اول فایل موجود را بررسی می‌کند |
| SERVER_COMMAND | وجود systemd/journalctl و مجوز sudo؛ کد خروج در گزارش ثبت شده است |
| موقعیت نامشخص / HTTP 429 | دسترسی Check-Host یا محدودیت نرخ؛ اطلاعات ناموفق ۵ دقیقه کش می‌شود |
| دادهٔ قدیمی | زمان اصلی مشاهده حفظ شده؛ بررسی تازه اجرا کنید |
| نتیجه نامشخص پس از restart/transfer | ابتدا وضعیت و journal را بخوانید؛ این برچسب به معنی برگشت موفق نیست |

## مسیرهای محلی

ویندوز: داده در `%LOCALAPPDATA%\GreFlow\data`، لاگ اجرا در `console.stderr.log` و `console.stdout.log`، کلید DPAPI در `%APPDATA%\GreFlow\console-master.key`.
لینوکس: `journalctl -u greflow-console`، داده در `/var/lib/greflow-console` و کلید خارج داده در `/etc/greflow-console/master.key`.
کلید اصلی را حذف نکنید؛ دیتابیس بدون آن اسرار SSH را بازیابی نمی‌کند.

## اینترنت و پراکسی

در ویندوز، دریافت اطلاعات IP از پراکسی تنظیم‌شدهٔ حساب ویندوز پیروی می‌کند. `HTTP_PROXY` / `HTTPS_PROXY` نیز پشتیبانی می‌شوند و اولویت دارند.
روی لینوکس متغیر پراکسی را در محیط سرویس تنظیم کنید. پراکسی HTTP فقط برای درخواست وب اطلاعات IP است؛ SSH مستقیم به سرور وصل می‌شود.
هیچ گواهی TLS نادیده گرفته نمی‌شود و هیچ پراکسی‌ای توسط برنامه روی سیستم فعال یا تغییر داده نمی‌شود.

## قبل از گزارش خطا

نسخه را با `greflow-console --version` ثبت کنید. سیستم‌عامل، مرحله و کد خطا و شرایط بازتولید را بنویسید.
گزارش قبل از اشتراک عمومی از نظر IP، نام کاربر، آدرس‌ها و اطلاعات داخلی بازبینی شود. اطلاعات سرور خود را در متن عمومی منتشر نکنید.
